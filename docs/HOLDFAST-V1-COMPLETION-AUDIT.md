## Follow-up code review

Two low severity issues were reported to the lead; production changes remain lead-owned:

- **RPC cooldown — resolved:** the lead added a 60-second request budget covering queue/cooldown and bounded numeric pacing inputs. A 3,600-second cooldown now fails promptly instead of sleeping and does not send a premature retry. An initial follow-up exposed permanent lane poisoning from a `1e308` overflow; the final code admits only safe finite millisecond cooldowns whose addition is safe. The focused regression proves the malformed header falls back safely and a subsequent healthy request succeeds. No external request was sent.

A new focused regression verifies the recovery address is available before signing, the original signature is exposed after the mocked failure, and exactly one signature/submission/confirmation occurs.
